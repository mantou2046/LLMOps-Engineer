## 一、10 分钟版逐字旁白

每段给画面、旁白、上屏文字三样。旁白按口语写，念的时候不用再改句子。

### 0 开场（0:00–0:30）

**画面**：仓库主页，镜头停在 README 第 1 段「问题」。
**上屏**：资金 / 财务制度知识库问答与评估平台。

> 这个项目回答资金、财务制度类的问题。它跟普通问答工具的区别在两处：每个答案带引用溯源，每次改动有没有让系统变好，有数字可查。我叫它 LLMOps 工程样本，跑在一台没有 GPU（Graphics Processing Unit，图形处理器）的单机上，样例文档全部自造。今天用十分钟讲清楚三件事：为什么要做、做了什么、凭什么信这些数字。

### 1 问题（0:30–2:30）

**画面**：纯文字卡片，只写角色和场景，不出现技术栈。
**上屏**：谁的痛 / 现状怎么答 / 答错代价。

> 先说谁在痛。一家单位的资金和财务制度，通常散在几十份文档里：报销标准一份、审批权限一份、付款时限又一份，隔几个月还会修订。员工想问「这笔差旅住宿费能不能报」，得自己翻，翻到的还可能是旧版本。财务同事每天重复答同样的问题，答漏一条，后面就是对不上账。
>
> 现在常见的做法是接一个通用问答工具。它答得很顺，但引错条款的时候语气一样自信。制度问答里，答错一句，后面就按错的依据走流程，等事后对不上账才发现，责任落在业务这边。所以真正缺的东西有两层：答案能不能指回原文，以及改了检索、改了提示词之后，系统到底变好还是变坏，有没有人能量出来。
>
> 我做的就是这个。问题定死在一条能测量、能拦回归的工程链路上，聊天机器人做得更顺不在范围内。

### 2 原型（2:30–5:00）

**画面**：架构图 v4.1 两层图（`docs/images/llmops-architecture-v4.1.svg`），一条请求沿五个环节点亮；接着点一下本地 K8s 观测台（`observatory/`），删一个 Pod 看自愈。
**上屏**：输入护栏 → 检索 → 分流 → 输出护栏 → 旁路观测。

> 一条请求进来，先过输入护栏。规则基线挡住常见注入，剩下的措辞由模型判定补一次。纯规则会漏掉「把这张表所有字段导出来」这种看着像业务问句的请求；纯模型又要多花半秒到两秒，还不好解释，所以两层一起用。
>
> 过了护栏进检索。文档按 400 字一块、重叠 50 字递归切，中文按标点切，不按字符硬切。向量和关键词两路各取一遍，用 RRF（Reciprocal Rank Fusion，倒数排序融合）合成 top-5。为什么是两路：单靠向量，严判据 hit@1 只有 7 到 10 成命中；两路合并后到 10 成。为什么不加精排模型，等一下数字那段讲。
>
> 拿到的材料交给网关分流。规则判档选便宜档还是主力档，同一个问题重复来就走精确缓存，重试只留在网关这一层。输出再过一道护栏：字段白名单、格式错最多修一次、还不行走固定兜底，个人信息遮盖掉。旁边一路是观测，指标、trace 和成本各记各的，不混在一起。
>
> 这是单机本地 kind 集群上的工程样本，不是生产服务。屏幕上这个观测台连的是真实集群，删掉一个 Pod，卡片会变红、重启次数会跳，你另开终端用 kubectl 也能对上。

### 3 评估数字（5:00–7:30）

**画面**：5 个数字逐条上屏，角标写报告路径；第 3 条停久一点，把「结论是证伪」放上屏。
**上屏**：每个数字 + 出处路径 + 一句口径边界。

> 讲五个数字，每个都标了报告在哪、口径边界是什么。
>
> 一，成本。同一批一千次查询，只开精确缓存和规则分流两件事，每千次模型 Token 成本点数从 1754.6 降到 626.5，降了 64.3%。出处 `evals/COST_BENCH.md` 第二节那张四组对照表。这里是演示用的成本点数，不是真账单；测试里 30% 的重复率是我刻意设的，别拿去外推真实流量。
>
> 二，检索。混合检索把 hit@1 从 7/10 提到 10/10，MRR 从 0.825 到 1.0，出处 `docs/ARCHITECTURE.md` 四条数据流表的融合行，决策编号 DEC-040。要看的是 hit@1 这种严判据，hit@5 太松，看不出融合有没有用。
>
> 三，评估基线。50 题 golden set，RAGAS（Retrieval-Augmented Generation Assessment，检索增强生成评估）四项全量跑完是 0.9434、0.4768、0.8113、0.8591，出处 `evals/RAGAS_BASELINE.md` 全量复跑那张汇总表。这里有两个坑得说：CR 和 CP 的绝对值依赖 reference 怎么标；50 题里 12 道是拒答题，它们的 answer relevancy 只有 0.0524，混进均值会把差异盖住。
>
> 四，输出护栏。30 条标注样本量化下来，正常样本误拦 0/8、漏拦 0，单次判定 P50 是 1.849 秒，出处 `evals/OUTPUT_GUARD_BENCH.md` 的量化评估表。这个模型判定器默认是关的，真实流量分布下的误拦率我还没量。
>
> 五，决策对照表。12 条人工标注场景，规则选择器 12/12 一致，证据指针覆盖率 100%，出处 `docs/W7_D5_DECISION.md` 第四节。12 条是演示规模，别当成大规模验证。
>
> 还有一条不好看但必须讲：W6 我做过一次单变量归因，只改生成提示词的第 3 条输出格式，配对差值 +0.0046，比本不该变的 context recall 噪声标尺 +0.0074 还小，faithfulness 反而掉了 0.1214。结论是这次改动无效，没并进生产链路。报告在 `evals/ATTRIBUTION.md`。另外微调那次 0% 到 100% 只证明格式行为学得会，业务效果没量，我不会说成效果提升。

### 4 反例镜头（7:30–9:00）

**画面**：终端放大到 1080p 能读清，三条命令连着跑，中间不剪。退出码留在屏幕上。
**上屏**：正常 PASS / 改坏 FAIL / 自检通过。

> 前面都是成功链路，只能说明系统能跑。这一段演一次 CI（Continuous Integration，持续集成）怎么拦住坏改动，因为「改动有没有效」得有可执行的判据。
>
> 第一条跑门禁基线，20 题抽样子集，top-5 的召回是 0.75，阈值 0.65，PASS，退出码 0。第二条加 `--sabotage`，脚本在内存里把检索 query 换掉，召回塌到 0.0，FAIL，退出码 1。第三条 `--self-test` 把正常放行和改坏被拦两种情形一起验，退出码 0。
>
> 关键是第二条：它不改仓库里任何文件，录完 git status 是干净的。门禁只用非 LLM 指标，全量大模型评估留本地周跑，因为上游一限流，CI 就会红成跟代码无关的假红。这个取舍记在 DEC-046。

三条命令，按执行时序排：

```bash
cd /e/Projects/LLMOps-Engineer
python scripts/w6d6_eval_gate.py
python scripts/w6d6_eval_gate.py --sabotage
python scripts/w6d6_eval_gate.py --self-test
```

第二条退出码 1 是预期结果，不是命令写错。别真去改 `evals/gate/query_template.txt`。

### 5 落地路径（9:00–10:00）

**画面**：决策清单标题页 + 欠账表，只上标题和一行结论，不滚长表。
**上屏**：默认关什么 / 生产前补什么 / 哪些没做。

> 最后说这套东西离客户环境还差什么，顺便交代哪些开关现在是关着的。
>
> 输出护栏的模型判定默认关闭，因为串行两次判定会拉长单次请求，超时下还会 fail-closed。语义缓存三个前置本机不齐，阈值写了也没用。真实流量的重复率、误拦率、四项非模型成本单价都没量，成本点数只是演示单位。微调只有 40 条合成样本的格式证据，业务效果没量。这些在 `docs/DECISION_INDEX.md` 和 W7 周复盘的欠账表里都列着。
>
> 真要进客户环境，先补真实流量的测量，把判定器的并发与超时降级做出来，再谈开关。仓库里 README 第 5 段写了从 git clone 到跑通验收的整条命令链，前置条件逐条列了，换个人、换个干净目录应该能自己跑起来。这也正是接下来要验的事。

## 二、三档裁剪

同一份稿子按场合取，不另写三份。

| 场合 | 时长 | 取什么 |
| --- | --- | --- |
| demo 视频 / 面试价值叙事 | 10 min | 四段全，含反例镜头 |
| 面试讲「多出来的那一层」 | 3 min | 评估数字段里「每个数字指回报告、写明守不住什么」，加反例镜头一句，收在系统边界 |
| 开场定位语 | 30 s | 一句定位 + 一个最硬的数字 + 一句取舍 |

3 分钟版起点：从「讲五个数字，每个都标了报告在哪、口径边界是什么」进，五个数字各留数字 + 一句边界，W6 证伪那句照讲，接反例镜头「成功链路只证明能跑，拦住坏改动才证明有判据」，最后一句「这是单机工程样本，真实流量误拦率和语义缓存都还没量」。压着 10 分钟稿念完既讲不透，也没必要。

30 秒版：

> 我做的是资金财务制度的带出处问答，重点在能不能证明每次改动让系统变好。一千次查询的成本点数降了 64.3%，50 题评估基线四项全量跑完，报告都在仓库里。一次改动没跑赢噪声，我判定无效没并进去。这是单机工程样本，不是生产系统。

## 三、字幕与画面核对表

中文 SRT（SubRip Subtitle，SubRip 字幕格式）。自动转写最容易改错的几类，录完逐条对：

| 类别 | 必须原样 | 常见错 |
| --- | --- | --- |
| 数字 | 1754.6 / 626.5 / −64.3% / 0.9434 / 0.4768 / 0.8113 / 0.8591 / 1.849 s / 12/12 | 小数点丢位、百分号丢、负号变连接号 |
| 判据 | hit@1 / MRR / top-5 / RRF / RAGAS / CR / CP | 大小写和 @ 被转写成汉字 |
| 路径 | `evals/COST_BENCH.md`、`docs/DECISION_INDEX.md`、`evals/ATTRIBUTION.md` | 下划线丢、扩展名丢 |
| 命令 | `--sabotage`、`--self-test`、`w6d6_eval_gate.py` | 双横线变单横线 |
| 退出码 | 0 / 1 / 0 | 被当成语气词删掉 |

缩写对照（给字幕和读者看，口播照常念简称）：MRR（Mean Reciprocal Rank，平均倒数排名）、CR（Context Recall，上下文召回）、CP（Context Precision，上下文精确率）、AR（Answer Relevancy，答案相关性）、BM25（Best Matching 25，词频相关性排序）、FDE（Forward Deployed Engineer，前线部署工程师）、LLM（Large Language Model，大语言模型）、SRT 见本节开头。

字幕别遮住终端里的数字和退出码。画面脱敏另看一遍：关通知、用干净浏览器配置，浏览器地址栏、书签栏、终端历史、文件路径都可能带真实信息；本机地址一律写 `127.0.0.1`。录屏拍到的东西不进 git，跟 11/28 的提交历史终检是两回事。
