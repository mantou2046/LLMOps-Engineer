> 任务卡 11/20 的硬要求：**每个结论都要有 11/19 实测或 W6 数字撑着**。本文所有数字后面都带证据编号，索引见 §6。
> 2026-11-10 更新：W7 D4 已在 Kaggle T4 补跑真 LoRA，`E-FT-2` 从「真训练未跑、效果未量」改为「小样本格式证据已量、业务效果未量」。默认顺序与「先 RAG，微调保持候选」的结论不变，见 §5 / §7。

## 1. 一页结论

> **默认顺序是 Prompt → RAG → 微调，不是三个并列选项。**
> 先问「问题出在哪」：指令没说清就改 Prompt，缺最新/私有知识就上 RAG，只有「行为长期不稳定且已有足量高质量样本」才评估微调。
> 本项目的实际答案是：**先 RAG，不够再微调**。W6 已经把 RAG 的检索层做实（RRF 融合 hit@1 7/10→10/10、MRR 0.825→1.0，E-RAG-1）。微调这条线 11-10 在 Kaggle T4 跑通了真 LoRA，但只在 40 条合成样本、20 条留出上验到「格式行为能学会」，业务效果**仍未量化**（E-FT-2）。

把三句话记住，比记住结论本身有用：

1. **别用微调更新知识。** 制度每月改，改检索库是一次数据更新，重新训练是一次工程 + 评估 + 上线，还要重新验收（E-RAG-1 / E-FT-2）。
2. **改 Prompt 不等于会提分。** W6 D5 做过单变量 A/B：answer relevancy 只动 +0.0046，比不该变的 context recall 噪声 +0.0074 还小，判定**不采纳**（E-PROMPT-1）。任何「优化 prompt 提升 X%」都要先过噪声标尺。
3. **先说清怎么判，再谈效果。** 本项目先花了整周建评估体系（50 题 golden set、RAGAS 四项、非 LLM 门禁），才敢说「哪条改动有效」（E-RAG-2 / E-RAG-3）。

## 2. 三条路径对照

| 维度 | Prompt（提示词） | RAG（检索增强生成） | 微调（LoRA 等） |
| --- | --- | --- | --- |
| 解决什么 | 指令没说清、输出格式不稳 | 缺最新 / 私有知识、答案要可追溯 | 稳定的风格 / 格式 / 工具选择行为 |
| 什么时候先试 | 规则能用指令或少量范例说清 | 知识常变、要引原文、模型权重里没有 | 行为长期不稳 **且** 有足量高质量样本 |
| 效果证据 | W6 D5 单变量 A/B 判定不采纳（E-PROMPT-1）；W7 D2 结构校验 + 固定兜底（E-PROMPT-2） | RRF hit@1 7/10→10/10、MRR 0.825→1.0（E-RAG-1）；50 题 RAGAS 四项 0.9434 / 0.4768 / 0.8113 / 0.8591（E-RAG-2）；门禁 IDBasedContextRecall@5 0.75（E-RAG-3） | **业务效果未量**（E-FT-2）；已量到的只有小样本格式证据：Kaggle T4 上 Qwen2.5-0.5B + LoRA r=8，留出 20 条格式符合率 0%→100%、分类准确率 0%→100%；数学实跑 LoRA r=4 参数 12.5% / 产物 12.8%、r=1 学不全（E-FT-1） |
| 成本 | 几乎为零，改动即生效 | 多一次检索；rerank 精排净增 2.2–2.4 s（默认不开，E-RAG-4） | 训练 / 部署 / 回归评估都要成本；本次云端训练 8.2 s、峰值显存 2890 MB、adapter 2,175,168 B（免费配额内，不是业务成本） |
| 延迟 | 无额外链路 | 向量检索约 4 ms；加 rerank 会到秒级（E-RAG-4） | 推理不增加链路；真机训练耗时已量（8.2 s / 40 条，T4），不可外推到生产规模 |
| 维护难度 | 最低，改文本即可 | 中：要维护语料、切法、索引与门禁 | 高：数据版本、训练、评估、adapter 版本全要管 |
| 可追溯 | 弱 | **强**（答案能追到检索块） | 弱（知识烘进权重，改不动也追不回） |
| 失败模式 | 改了没用还以为有用（E-PROMPT-1） | 检索漏了就答错；阈值 / probes 配错会静默掉分（E-RAG-3） | 过拟合、样本偏差、秩容量不足（E-FT-1） |

**成本侧补充**：如果瓶颈是「重复问题太费钱」，不该换模型，该加缓存与分流 —— W7 D3 同条件压测每千次成本点数 1754.6→626.5（−64.3%），其中精确缓存命中率 28.4% 恰好等于设定的 30% 重复率（E-COST-1）。护栏也是成本：W7 D2 的真实模型判定单次 P50 1.849 s / P95 10.004 s、一次结构化回答额外约 513 tokens，所以默认关闭（E-GUARD-1）。

## 3. 判断流程（可照着念）

```
① 知识会更新 / 要能追溯到原文 / 是私有知识？
      → 是：RAG。格式问题另加结构校验，两件事分开解。
      → 否：↓
② 输出格式、风格、工具选择长期不稳定？
      → 是，且有足量高质量样本：才评估微调（⚠️ 已有 Kaggle T4 小样本格式证据，但业务效果仍需真实任务评估）
      → 是，但没样本：先写清 Prompt + 结构校验，边跑边攒样本
      → 否：↓
③ 规则能说清吗？
      → 能：Prompt（+ 结构校验）
      → 不能：先 Prompt 起步，配回归评估集；不够再 RAG，最后才评估微调
④ 横切：成本敏感 → 叠加缓存 / 分流；安全敏感 → 叠加输出护栏（默认关闭）
```

**优先级的两处硬判据**（已在场景集里验证）：

- 「知识会变」压过「有样本 + 行为不稳」：S10 仍判 RAG。用微调补知识是经典反模式（S08）。
- 「可追溯」是硬约束：S12 即使格式飘，主键仍是 RAG，格式另解。

## 5. 直接回答面试原题：「什么情况下才该微调？」

> 三个条件同时满足才评估：**① 问题出在稳定的行为（格式、风格、工具选择），不是知识；② 改 Prompt 加结构校验已经试过且确实不够（要有 A/B 数字，不是感觉）；③ 手上有足量高质量任务样本和一套能判「有没有变好」的评估集。**
> 本项目目前**不满足第 ② ③ 条的完整证据**：W6 D5 的 A/B 证伪了一次 prompt 改动（E-PROMPT-1）。微调侧 11-10 已在 Kaggle T4 跑通真 LoRA，留出 20 条格式符合率与准确率 0%→100%（E-FT-2），但那是 **40 条合成训练样本、4 类词语分类**的格式学习，不是在真实任务上做的 A/B，也不构成业务收益数字。所以当前结论仍是「先 RAG，微调保持候选」，不写成「微调能带来 X 提升」。
> 2026-11-10 补记：欠账里「真训练一次都没跑」这一条已清掉，改判 D4 整项完成；但「足量高质量任务样本 + 能判有没有变好的真实评估集」仍未满足，面试答案不改口。要改口得先在真实任务上做一次带评估集的单变量 A/B。

讲法提醒（W6 周复盘的教训）：**把理由讲清比结论本身重要**。两轮单变量 A/B 都是「不采纳」，周复盘没有「提升了多少」可写，如实写清改了什么、哪个指标动了多少、有没有副作用，比凑一个好看数字有用。

## 7. 边界与欠账

- **业务效果仍未量**：这是本表最大的缺口。所有微调相关结论都带 `E-FT-2` 与「效果未量」声明，不写成收益。11-10 云端补跑量到的是 40 条合成样本上的格式行为，不等于真实任务收益。
- 12 条场景是演示规模，不等于真实业务流量分布；规则选择器是教学用判据，不是生产路由组件。
- 数字都来自 W6/W7 已落库报告，本文没有新编实验数据；RAGAS 的 CR / CP 绝对值依赖 `reference`，仍按 W6 口径谨慎解读。
