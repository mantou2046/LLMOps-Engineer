# D5 扩展：应拒答与 boundary 的 A/B 配对（2026-11-08）

> 收口 11/15 欠账第 8 条：**把 12 道应拒答 + 3 道 `boundary` 纳入 D5 的单变量 A/B 配对样本**。
> D4 全量 50 题早已给这 15 题分组报分（`RAGAS_BASELINE.md` §全量复跑），那是横截面基线；本实验看的是**同一改动在这 15 题上的配对变化**。
> 口径按用户拍板：**拒答题单独成组、以确定性行为判据为主，ragas 四项只作旁证，不与 10 题可答题混进同一均值**。

## 实验设计（控制变量）

| 项 | A 组 | B 组 |
| --- | --- | --- |
| 题目 | `golden_set` 中 `must_refuse` 或 `type=boundary` 的 15 题（12 + 3） | 同 15 题 |
| 回答 | 逐字复用 `evals/out/w6d4/responses.jsonl`（已生成，不重跑） | 重新生成 |
| 生成模型 / 通道 | `deepseek-v4-flash` / 本机网关 `.env` 原始 `LLM_PRIMARY_*` | **同模型同通道** |
| 检索上下文 / 问题 / reference | 每题 5 个块，来自 D4 | **逐字复用 A 组，不重切不重排** |
| system prompt | `PROMPT_A`（D4 原版） | `PROMPT_B`（**只改第 3 条输出格式约束**） |
| 裁判 | `glm-5.3-flash`（Experiential `/v1`，独立固定裁判） | 同一次 `evaluate()` 里 A/B 按题号交错 |

- **通道分离**：生成端读 `.env` 原始配置，不受进程环境覆盖；裁判通道由启动器注入 `RAGAS_JUDGE_BASE_URL` / `JUDGE_API_KEY`，凭据只在进程内存，不落盘、不进日志。这样避免把「换裁判」误变成「换生成通道」。
- **控制变量校验 15/15**：问题、5 个上下文、`reference` 逐字一致；B 组模型与 `prompt=B` 标记统一；A 组无 `[生成失败]`。
- 产物隔离在 `evals/out/w6d5_refusal/`（gitignore），**没有触碰**既有 `w6d5` 的 `scores.jsonl` / `comparison.json`。
- 脚本 `scripts/w6d5_refusal_ab.py`；启动器只负责把 `RAGAS_JUDGE_BASE_URL` / `JUDGE_API_KEY` 注入进程环境（本机专用、不入仓，凭据值不落盘）。

## 行为分（主判据）

| 组 | n | A 正确拒答 | B 正确拒答 | 翻转 | A/B 平均字数 | A/B 元信息命中 |
| --- | --- | --- | --- | --- | --- | --- |
| `refuse`（应拒答） | 12 | **11/12** | **11/12** | **0** | 34.1 → 26.2 | 0 → 0 |
| `boundary`（可答，边界题） | 3 | 1 次误拒答 | **0 次** | `g038`（拒答 → 正常回答） | 142.0 → 180.0 | 0 → 0 |

- 12 道应拒答题里 11 题 A/B 都回「资料中没有覆盖这个问题，无法回答。」（17 字），**零翻转**；B 组平均字数更短，是 prompt 第 3 条「1–2 句、不要客套」生效的表现。
- `g049`（「kind 和 minikube 哪个更好，给 1–10 主观评分」）A/B **都没拒答**，都给了「kind 更好，9/10」这类主观结论——这是**题库基线就没过**的一题，不是本次改动造成的，与 D3 复标验收欠账相关，本实验未改题库。
- `boundary` 组 A 有 1 次误拒答（`g038` 集群节点容量题），B 变成正常回答；方向是好的，但 n=3 只作线索。

**结论：prompt 改动没有在这 15 题上造成拒答行为退化。** D5 主实验里 `g002`（可答 `single_hop`）被 B 组误判成拒答、faithfulness 从 1 掉到 0，那次**没有复现为系统性倾向**。

## ragas 四项（旁证，按组独立报分）

| 组 | 指标 | A | B | 配对 Δ | n |
| --- | --- | --- | --- | --- | --- |
| `refuse` 12 | faithfulness | 0.9167 | 0.8056 | **−0.1111** | 12 |
| | answer relevancy | 0.0305 | 0.0673 | +0.0369 | 12 |
| | context recall | 0.6667 | 0.9167 | **+0.2500** | 12 |
| | context precision | 1.0000 | 1.0000 | 0.0000 | 11 |
| `boundary` 3 | faithfulness | 1.0000 | 0.9778 | −0.0222 | 3 |
| | answer relevancy | 0.3784 | 0.7865 | +0.4081 | 3 |
| | context recall | 0.8333 | 0.8333 | 0.0000 | 3 |
| | context precision | 0.7778 | 0.7778 | 0.0000 | 3 |

三条读数：

1. **CR 漂了 +0.25，是裁判口径不稳的证据，不是检索变好。** `context_recall` 不读 `response`，理论上 A=B 应恒等（D5 一直拿它当噪声标尺）。这 12 题的 `reference` 写的是「文档里没有相关信息，应说明未覆盖并拒答」——**期望行为，不是事实答案**，裁判在 A/B 两批里给出不同判断。同一组 CP 却 11/11 对 A=B=1.0000 恒等。两把噪声尺一把稳一把飘，说明**应拒答题的 ragas 绝对值不可解释为检索或生成质量**，只能当分组旁证。
2. **faithfulness 两组都回退**（−0.1111 / −0.0222），方向与 D5 主实验、独立裁判交叉验证一致。
3. `boundary` 的 AR Δ +0.4081 主要来自 `g038` 的 0 → 0.9325（A 误拒答 → B 正常回答），与行为翻转对得上；另两题是 +0.558 / −0.2662，逐题波动大、n=3 不作统计结论。

## 缺口与止损

- `g049` 的 **B 组 context precision** 在全量批次和断点补跑中各撞一次 180 秒 `TimeoutError`（与 D4 里 `g006` 的 CP 四次超时同类坑）。按库里「同一步失败两次即停」的纪律**不再重试**，如实留 1 个 NaN：refuse 组 CP 配对 11/12、全量 CP 14/15，其余 **119/120 个分数齐全**。**没有**用 A 组值回填、没有编数字。
- 缺分不影响判定：CP 是噪声标尺，且行为分、faithfulness、AR、CR 全部 15/15 成对齐全。
- 拒答题的 `reference` 是期望行为，D3 真人双标验收仍未过，本报告的 ragas 绝对值继续打折扣。

## 结论

**「改动不采纳」维持，DEC-045 不改。** 这次扩展没提供任何采纳理由：faithfulness 在可答题（D5 主实验）和这 15 题上都回退，行为分也没有收益可写。

⚠️ **但理由权重要在周复盘里调整**：D5 主实验把「B 组多一次误拒答」列为判定依据之一，这 15 题上零翻转、boundary 还少一次误拒答，说明那更像是**单题/裁判噪声，而非 prompt 导致的系统性拒答倾向**。判定继续由「faithfulness 回退 + AR 变化接近噪声 + 逐题离散大」支撑，别把 `g002` 写成普遍现象。

新增方法论：**应拒答题的评估以确定性行为判据（是否按预期拒答、是否翻转）为主，ragas 四项只报分组旁证**，不与可答题混进同一均值，也不与 D4 全量横截面基线直接相减。

## 复现

```bash
# 裁判通道由调用方注入（凭据只在进程环境里，不写文件、不入仓）
export RAGAS_JUDGE_BASE_URL=https://api.experientiallabs.ai/v1
export JUDGE_API_KEY=<有效 key>
python scripts/w6d5_refusal_ab.py --batch-size 4 --workers 2 \
    --batch-wait 5 --judge glm-5.3-flash
# 只重建汇总、不联网：
python scripts/w6d5_refusal_ab.py --report-only
```

生成端刻意**不覆盖** `LLM_PRIMARY_*`：脚本直接读 `.env`，保持与 A 组同一本机网关通道；这也是这次能只变 prompt 一个变量的前提。首次建议 `--limit 2` 试水。分数逐题落盘、断点续跑；`--report-only` 可随时重建 `summary.json`。产物 `evals/out/w6d5_refusal/` 按仓库惯例被 gitignore，数字以本报告为准。
