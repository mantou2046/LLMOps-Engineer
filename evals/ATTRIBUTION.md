## 结论

按「answer relevancy 低 → 动生成层」这条对照表规则，只改生成端 prompt 的第 3 条输出格式约束，跑了一组 A/B。**目标指标没有可辨识的提升，副作用却很明确**：

| 指标 | A（原 prompt） | B（改第 3 条） | 配对 Δ | 配对题数 |
| --- | --- | --- | --- | --- |
| answer relevancy（目标） | 0.6223 | 0.6269 | **+0.0046** | 10 |
| faithfulness（副作用） | 0.9214 | 0.8000 | **−0.1214** | 10 |
| context recall（噪声标尺） | 0.8667 | 0.8741 | **+0.0074** | 9 |
| context precision with reference | 未跑 | 未跑 | — | 0 |
| 确定性余弦 question↔response | 0.7560 | 0.7741 | +0.0181 | 10 |

`context_recall` 不读回答，只依赖检索上下文和标准答案，A/B 用的是同一份，理论上差值必须为零。实测 +0.0074，比目标指标的 +0.0046 还大。目标指标逐题 5 涨 5 跌、标准差 0.3718，均值那点变化完全盖在波动里。所以这次改动**不采纳**，任务卡 11/13 记录的是「证伪了一条归因假设」，不是「优化了指标」。

改动本身确实生效：平均回答 139.7 → 118.4 字，带「根据资料」「块 N」这类元信息的题从 4 降到 1。但 B 组把 g002 能答的题判成了拒答，faithfulness 从 1 掉到 0，这是真实的回退，不是噪声。

## 一、为什么挑 answer relevancy

D4 的 10 题小样基线是 faithfulness 0.9714 / answer relevancy 0.5817 / context recall 0.9200 / context precision 0.8988，最低的是 answer relevancy。D4 报告给的解释是回答里带了元信息、本地 `bge-small-zh-v1.5` 对中文短问句与长回答的余弦整体偏低，两条都指向生成层。

⚠️ 本次 A 组的 0.6223 不是 D4 的 0.5817。裁判换了：D4 用网关 `auto` 路由，本次为控制变量改用固定别名 `deepseek-v4-flash`。两组 A/B 都在同一裁判、同一批 `evaluate()` 里交错评分，只比较本次内部的相对变化，不拿 D4 的绝对值当基线。

## 二、指标 → 该改哪一层

| 指标 | 量的是什么 | 读不读 response | 要不要 reference | 低分说明 | 该动哪层 | 本次改动能否动到它 |
| --- | --- | --- | --- | --- | --- | --- |
| context recall | 标准答案的要点被检索结果捞回多少 | 不读 | 要 | 该找的资料没回来 | 检索 | 不能，检索层零改动 |
| context precision | 相关块在结果里排得靠不靠前 | 不读 | 要 | 混进无关块或好块排太后 | 检索排序 | 不能 |
| faithfulness | 回答里的断言有多少能在上下文找到依据 | 读 | 不要 | 生成时掺了资料外的内容 | 生成 | **能，且确实掉了** |
| answer relevancy | 从回答反推问题，与原问题算余弦 | 读 | 不要 | 答非所问或拒答太多 | 生成 / 问题理解 | 能，但本次没动 |

组合读法比单项有用：recall 高而 faithfulness 低，是料给对了模型乱说，改生成；recall 低而 faithfulness 高，是模型老实但没料，改检索。这两行是任务卡验收要能脱口而出的部分。

本次实验给这张表补了一列「读不读 response」。这一列决定了哪些指标能当噪声标尺，比「该动哪层」更早该问。

## 三、实验怎么保证只改一个变量

A 组 = D4 已产出的 `g001`–`g010` 回答（原 prompt）。B 组 = 同十题、逐字复用 A 组每题的 5 个检索块，只换 prompt 重新生成。没有重切语料、没有重跑 RRF、没有换题库或标准答案。

固定的量：

| 项 | 值 |
| --- | --- |
| 题目 | `golden_set.jsonl` 的 `g001`–`g010`（与 D4 小样同批） |
| 语料 / 切法 | `evals/corpus/` 六篇冻结快照，递归 B(400/50)，330 块 |
| 检索 | `bge-small-zh-v1.5` 余弦 + jieba BM25，RRF(k=60)，top-5 |
| 检索上下文 | B 组逐字复用 A 组，不重排 |
| 标准答案 | 同一份 `reference` |
| 生成模型 / 参数 | `deepseek-v4-flash`，`temperature=0`，`max_tokens=400` |
| 裁判 | `deepseek-v4-flash` 固定别名，A/B 按题号交错放进同一次 `evaluate()` |
| embedding | `models/bge-small-zh-v1.5`（512 维，L2 归一化） |
| 指标 API | ragas 0.4.3 legacy |

唯一变量是 system prompt 的第 3 条，第 1、2、4 条逐字未动：

```
A：3. 回答控制在 2 到 4 句，直接给结论和依据；不要复述问题，不要加「根据资料」这类前缀。
B：3. 回答只用 1 到 2 句：第一句直接给结论，并带上问题里问的那个对象或术语；第二句给依据。不要复述整句问题，不要加「根据资料」「块 1」这类前缀或出处说明，不要写总结、提示语或客套话。
```

两个额外的度量设计：

1. **噪声标尺**。`context_recall` 和 `context_precision` 的输入里没有 response，A/B 的真实值必然相等。把它们的 A/B 差值记下来，就是这套裁判 + 这套题的噪声量级。目标指标的变化要先跟这把尺子比，而不是跟零比。
2. **确定性交叉验证**。本地 bge 直接算 `cos(question, response)`，完全不调 LLM，可复现，用来判断 LLM 打分的方向是不是靠谱。

差值一律用「A/B 同题都有分」的配对样本算。某组缺一题时不做跨题均值比较，避免口径不等。

## 四、结果与判读

### 4.1 目标指标：变化小于噪声

| 项 | answer relevancy | context recall（噪声标尺） |
| --- | --- | --- |
| 配对均值 Δ | +0.0046 | +0.0074 |
| 逐题 Δ 标准差 | 0.3718 | 0.2047 |
| 逐题 \|Δ\| 均值 | 0.2639 | 0.0963 |
| 涨 / 跌 / 平 | 5 / 5 / 0 | 1 / 1 / 7 |
| 配对题数 | 10 | 9 |

连理论上该恒等的 context recall 都动了 +0.0074，单题上 `g003` 从 0.2 判到 0.667、`g005` 从 0.6 判到 0.2，差到 ±0.4 以上。这两题的检索上下文和标准答案一模一样，差值只能来自裁判。目标指标那 +0.0046 落在这个噪声地板里，不能叫提升。

answer relevancy 自己也不稳定：`g002` 从 0.7644 掉到 0，`g004` 从 0 涨到 0.5605，`g009` 从 0.4310 涨到 0.9830。10 题里有 5 题在跌，均值被两头的极端值凑平了。

### 4.2 副作用：faithfulness 掉了 0.1214

| 题 | A → B | 回答发生了什么 |
| --- | --- | --- |
| g002 | 1.0 → 0.0 | B 组把能答的题判成「资料中没有覆盖这个问题，无法回答」，回答只剩 17 字 |
| g007 | 1.0 → 0.0 | 回答语义与 A 几乎相同，只是句式重排，分数却归零 |
| g001 | 0.7143 → 1.0 | 去掉「块 1 和块 3」这类元信息后，断言都能对上资料 |
| g004 | 0.5 → 1.0 | 同上 |

净变化 −0.1214，逐题 2 涨 2 跌 6 平、标准差 0.4674。`g002` 是改动带来的真实回退，改后的首句要求可能让模型更倾向拒答。`g007` 更像是裁判不稳定，同一层意思换个句式就从 1 掉到 0。两者混在一起，说明光看均值也无法把「改坏了」和「判飘了」分开。

### 4.3 改动生效，但没有换来指标改善

| 形态 | A | B |
| --- | --- | --- |
| 平均字数 | 139.7 | 118.4 |
| 平均句数 | 1.5 | 1.6 |
| 带元信息的题数 | 4 | 1 |
| 出现拒答短语的题数 | 0 | 1 |

确定性余弦 0.7560 → 0.7741（10 题里 8 涨 2 跌），方向和目标指标一致，幅度也只有 0.0181；`g002` 一题就掉了 0.4681。去掉元信息、压短回答确实让向量更贴题一点，但远不足以抵消一次误拒答。

### 4.4 判读

按对照表「answer relevancy 低 → 改生成层」去改，结果目标指标没动、faithfulness 掉了、还多了一次误拒答。这条假设在小样上没有得到支持。更可能的解释在尺子这一侧：中文短问句与长回答的 embedding 尺度、拒答题混进 10 题小样、以及裁判在单题上能飘 0.4。继续调 prompt 属于在噪声里找信号，先停手。

## 五、可复用的归因流程

1. 先写清每个指标读哪些输入。读不读 response 决定了它会不会被你这次改动碰到。
2. 找出「不该变」的指标当噪声标尺，和实验组一起跑，别事后补。
3. 均值变化先跟噪声比，再跟零比。噪声比变化还大就别写「提升」。
4. 看逐题分布（标准差、涨跌幅、极端题），别只看均值。
5. 单独确认改动是否生效（本题用回答形态统计）。改动生效和指标改善是两件事。
6. 一次只改一个变量，把控制变量清单写进脚本和产品文件，能被别人核。
7. 组合读法定位层：recall 高 + faithfulness 低改生成，recall 低 + faithfulness 高改检索。
8. 不显著就停手，别顺着噪声继续调；把「没提升」和原因一起留档，这本身就是结论。

第 2 条是这次最值钱的一条。没有噪声标尺，+0.0046 很容易被写成「prompt 优化后 relevancy 小幅提升」。

## 六、踩坑与局限

- **`qwen3.8-27b` 额度耗尽**。最初选它当固定裁判，短 prompt 压测 4/4 成功、约 0.3 秒、输出干净 JSON；一上 ragas 的密集调用就返回 429，网关原文 `All models exhausted: 2 routes checked (1 rate-limited or on cooldown, 1 prompt too large for the model)`、`Soonest reset ~18h`。那一批 20 题几乎全是 NaN，已另存 `evals/out/w6d5/scores.qwen429-invalid.jsonl` 留档，没有混进结果。
- **长 prompt 下多数模型不输出 JSON**。用 2057 字的真实上下文压测：`glm-5.2` 只回三个反引号，`qwen3.8-flash-next` / `qwen3.5-397b` / `glm-4.7-flash` / `auto` 都先输出思考过程。只有 `deepseek-v4-flash` 给出合法 JSON（约 26 秒/次），所以裁判最终退回它。
- **裁判和生成是同一个模型**，存在同模型自评偏高的风险，且前面几轮 429 就是它挂在 AMD 上引起的。这是为了控制变量做的妥协，换到独立固定裁判后应重跑一套交叉验证。
- **样本只有 10 题**，`g001`–`g010` 全是可答题，12 道应拒答与 3 道 `boundary` 不在里面。`g002` 这次是被误判成拒答的，一旦按题型分组报分，它会落到另一组。
- **D3 复标验收仍未通过**（三轮一致率 55.3% → 68.1% → 70.2%，预设 0.8），标准答案一致性存疑；D4 也只跑了 10 题小样、不是全量。这两条欠账会传导到本报告里所有依赖 `reference` 的指标。
- **context precision 没跑**。它不读 response、理论 A=B，D4 里 `g006` 又反复触发 ragas 内部 180 秒超时；在裁判额度受限时优先保目标指标、生成层副作用和一个噪声标尺，这一项留到额度恢复后补。
- **context recall 少一题配对**：`g006` 的 A 组评分超时记 NaN，配对样本 9 题。全部有分题的均值另列在 `comparison.json` 的 `averages` 里，口径不等，不作为结论依据。
- 单批 `evaluate()` 要 3–6 分钟，三项指标分三次跑完约 26 分钟。前台命令会被 300 秒上限掐断，用后台任务 + 断点续跑（脚本逐题落盘，重跑只补缺的指标）。
